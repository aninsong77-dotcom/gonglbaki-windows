## 1. 핵심 사전 발견 사항 (계획에 직접 반영)

1. **11일 전 정반대 방향 전환 이력**: `server/app.py` 598행 주석에 "2026-07-09 Qwen3-4B → Kanana 교체"가 명시돼 있다. 당시 Qwen3-4B는 한국어 자연스러움·속도(2~3배 느림)·용량(2.5GB vs 1.5GB) 열세로 **탈락한 모델**이었다(근거: `요약모델_테스트/비교결과*.md`, MEMORY `project_kanana_engine_swap.md`). 이번 로드맵은 "대화형 채팅에는 Qwen이 필요"라는 새 이유로 되돌리는 것 — **품질 열세 자체가 해소된 게 아니라 트레이드오프를 다시 선택한 것**임을 리스크로 명시(§4 위험 지점).
2. **배포 모델은 "공식 원본 직접 변환"만 허용하는 내부 원칙이 이미 있다**: `app.py` 602~604행 주석 — "제3자 변환본 미사용", 카카오 공식 저장소에서 직접 GGUF 변환·양자화 후 GitHub 릴리스 업로드. `요약단어_테스트/Qwen3-4B-Q4_K_M.gguf`(현재 로컬에 있는 프리뷰용 파일)의 출처가 공식 원본 직접 변환인지 확인되지 않았다 — **티켓①에 "모델 교체"뿐 아니라 "출처 검증/재변환" 작업이 포함되어야 한다.** (§안전·보안 우선순위와 직결) **이 원칙은 이 앱이 배포하는 모든 gguf에 적용되는 보안 기준이지 요약 모델(Qwen3-4B) 전용이 아니다 — 티켓③에서 새로 도입하는 임베딩 모델(bge-m3 계열)에도 동일하게 적용한다(리뷰에서 지적된 이중 잣대 수정, 03-reference-rag.md §2.4.1).**
3. **Index.tsx와 CaseDrawer.tsx는 현재 데이터 연결이 전혀 없다**: `Index.tsx`에서 `CaseDrawer` 임포트·렌더링(2842행) 외 `caseDrawerAPI`/`SessionRecord`/`sessionId` 참조가 0건이다. 두 탭은 `activeTab` 문자열로 전환되는 형제 컴포넌트(2836~2846행, 둘 다 항상 마운트·`display:none`)일 뿐 props도 콜백도 없다. **티켓④는 "이미 있는 연결을 확장"이 아니라 "처음 연결을 만드는" 작업**이다.
4. **`SessionRecord.analysis`에 새 파일을 붙이는 기존 방법은 "이미 존재하는 파일을 선택"뿐**이다(`CaseDrawer.tsx` `AttachSlot`, `caseDrawerAPI.selectFile` = 열기 다이얼로그, 저장 다이얼로그 없음). 채팅에서 만든 요약 텍스트를 바로 붙이려면 새 IPC가 필요한 게 아니라, **결정적 경로 규칙(예: `<사례폴더>/<회차번호>_분석_채팅.txt`) + 기존 `caseDrawerAPI.writeText`(236행 핸들러, 이미 임의 경로 쓰기 지원) + `SessionRecord.analysis` state 갱신**만으로 충분하다 — 신규 IPC 불필요(구조 설계와 일치, 확인 완료).
5. **hwpx 파싱은 외부 스킬 스크립트를 이식할 필요가 없다**: `app.py`에 이미 자체 hwpx 파서(`_hwpx_extract_preview`, 1640~1659행)가 있다 — zipfile + ElementTree로 문단/표를 순서대로 추출, 의존성 추가 없음. `~/.claude/skills/hwpx/scripts/hwpx2md.py`는 서식(줄간격·장평 등) 보존까지 하는 무거운 스크립트이자 **최종 사용자 PC에는 존재하지 않는 Claude 스킬 자산**이라 그대로 참조할 수 없다(경로가 `~/.claude/...`). RAG는 "텍스트 검색용"이라 서식 불필요(requirements §7 제외 범위와 일치) → **자체 파서 재사용이 정답, 신규 이식 불필요**. 이는 효율(불필요 의존성·중복 코드 최소화) 우선순위에 직접 부합.
6. **PDF 텍스트 추출 라이브러리가 Python 쪽에 전혀 없다**: `server/requirements.txt`에 PDF 관련 패키지가 없다. 신규 추가가 필요하다(§안전·효율 근거는 각 티켓 문서). *(참고: 이 판단은 Claude가 연구논문을 직접 파싱하는 맥락의 `parse_pdf` MCP 규칙과 무관 — 이 앱이 자체 서버 코드에서 상담학 강의자료 텍스트를 추출하는 완전히 별개의 소프트웨어 의존성 선택이다.)*
7. **마크다운 렌더러가 FE에 전혀 없다**(`package.json` 확인 — `react-markdown` 등 부재). 티켓②에서 신규 의존성 추가 여부를 명시적으로 결정해야 한다(§4, 티켓② 참조).
8. **모델 용량 표기가 이미 내부적으로 불일치한다**: `Index.tsx` 335행 `{dlMb}MB/2382MB`(하드코딩, 실제 다운로드 진행률 텍스트) vs 2627행 `/1452MB`(백엔드 `model_size_mb` 값과 연동) vs 131행 "약 1.5GB"(다른 모델 목록 설명) — **기존 코드에 이미 존재하던 표기 불일치**이며 티켓①에서 Qwen 용량으로 갱신할 때 이 3곳 전부(그리고 320·333·340·341행) 놓치지 않아야 한다.

## 3. 티켓 분리 (requirements.md 그대로, 순서 고정)

| 티켓 | 스프린트 | 선행 조건 |
|---|---|---|
| ① Qwen3-4B 엔진 통합 | Sprint 1 (단독) | 없음 |
| ② 대화형 채팅 UI | Sprint 2 (단독) | ① 완료 |
| ③ 참고자료 RAG | Sprint 3 (백엔드 파이프라인은 Sprint 2와 병렬 가능, 접합부만 Sprint 2 완료 후) | ② 완료(접합부만), 파싱/임베딩 자체는 ①만 있으면 착수 가능 |
| ④ 사례서랍 연동 | Sprint 4 | ② 완료(필수), ③ 완료(조건부 — 아래 규칙 참조) |

**③↔④ 의존 관계 확정 규칙(리뷰 반영, Critical 수정)**: requirements.md는 "③과는 독립적이나 축어록+참고자료 동시 활용 요구사항 때문에 ③ 이후 완료가 자연스럽다"고 서술했는데, 이를 "권장"으로만 남기면 04 문서의 완료 조건 중 "축어록 컨텍스트 + 참고자료(RAG) 컨텍스트 동시 활용 질의 정상 동작" 항목과 모순된다(③ 없이는 애초에 검증할 대상 자체가 없음). **아래로 확정한다**:
- ④는 ③ 완료 **없이도** 착수·완료 선언이 가능하다(핵심 요구사항 "회기 선택→채팅 컨텍스트 연결"·"결과 저장"은 ③과 무관하게 완결됨).
- 단, 04 완료 조건의 "축어록+참고자료 동시 활용" 항목은 **③이 완료된 시점에만 검증 대상**이 된다 — ③ 미완료 상태에서 ④를 완료 선언할 때는 이 1개 항목만 "③ 완료 후 별도 통합 검증 예정"으로 보류 표시하고 나머지 항목으로 ④ 완료를 선언한다. ③이 나중에 완료되면 이 1개 항목만 추가로 재검증한다(④를 다시 열 필요 없음).

## 4. 위험 지점 (사용자 지정 4대 우선순위 — 안전·보안·효율·안정성 기준으로 정리)

### 안전 (프라이버시·데이터 보존)
| 위험 | 대응 |
|---|---|
| 대화 히스토리 신규 저장소가 사례 폴더 밖(전역 위치)에 생기면, 사례별 축어록과 달리 사례 폴더를 통째로 옮겨도 대화가 안 딸려간다 | 티켓②에서 "세션 미연결 자유 대화"와 "④로 연결된 사례별 대화"의 저장 위치 분기 규칙을 문서로 확정(구조 설계 §5의 미확정 사항) — impl-planner 단계에서 확정하지 않으면 개발 중 임의 결정 위험 |

| 채팅 로그(디버그 로그 `~/gongulbaki_debug.txt`)에 축어록·참고자료 원문이 남을 가능성 | 기존 원칙 계승(`_analyze_ask_llm`의 786~790행 이미 "에러 본문에는 축어록 내용이 없고 서버 상태 메시지만" 원칙 적용 중) — 신규 `/api/chat/*`·`/api/reference/*`의 모든 `debug_log()` 호출도 동일 원칙으로 티켓②③ 완료 조건에 명시 |
| 외부 전송 경로 신설 | ①②③④ 전부 `llama-server`(로컬, 127.0.0.1) 호출만 — 신규 외부 API 호출 없음을 각 티켓 완료 조건에 재확인 항목으로 명시 |

### 보안 (하드코딩 비밀값 없음, API 노출 최소화)
| 위험 | 대응 |
|---|---|
| 신규 `/api/chat/*`·`/api/reference/*`·`/api/embed/*`가 `127.0.0.1` 바인딩 밖으로 노출되지 않는지 | 기존 서버 바인딩 설정 그대로 상속(신규 Flask host 설정 추가 금지) — 티켓②③ 완료 조건에 "신규 라우트가 기존 CORS/바인딩 설정 변경 없이 동작" 확인 |

| 참고자료 삭제(`DELETE /api/reference/{id}`) 시 경로 검증 없이 임의 경로 삭제 가능성 | id→경로 매핑을 서버가 관리하는 인덱스(JSON)로만 하고, 요청의 경로 문자열을 직접 삭제에 쓰지 않음 — 티켓③ 완료 조건에 명시 |

### 안정성 (기존 파이프라인 회귀 방지)
| 위험 | 대응 |
|---|---|
| Qwen ChatML(`/no_think`) 전환 시 map-reduce 요약 품질이 Kanana 대비 실제로 퇴행(§1-1의 과거 검증 결과) | 티켓① 완료 조건에 "Kanana 검증 때 썼던 동일 더미 대본으로 A/B 비교, 2차 검증에서 교정했던 4개 버릇(문장 수 초과·과제 오분류·행동 지어내기·reduce 항목 추가)이 Qwen에서도 재발하지 않는지" 항목 추가 — 지시문(`_ANALYZE_SYS_MAP_*`/`_ANALYZE_SYS_REDUCE`)을 Qwen ChatML로 그대로 옮기되 이 4개 규칙 문구는 유지 |
| `_ensure_llama_server`의 컨텍스트 크기(`-c 16384`)가 Qwen 토크나이저 기준으로도 안전한지(Kanana 실측 0.56토큰/자 기준으로 설정된 값) | 티켓①에서 Qwen 토크나이저 실측 후 `_reduce_partials`의 `LIMIT = 16000`자 값 재검증 — 과거 "컨텍스트 초과로 결과 빈 채 반환" 실사고(2026-07-09)가 재발하지 않도록 실사용 크기(조각 20개 이상)로 검증 필수(과거 교훈 그대로 적용) |
| **(Critical, 리뷰 반영) 채팅은 요약과 달리 "대화 히스토리 누적(②) + 축어록 전체(④) + 참고자료 조각(③)"이 매 턴 함께 쌓여 컨텍스트 초과가 1회성이 아니라 상시 반복될 위험** — 2026-07-09 실사고와 동일한 유형의 문제가 채팅에서는 훨씬 쉽게 재현 가능 | 티켓②-§2.3에 컨텍스트 예산 관리 규칙을 확정: 초과 시 (1순위) 참고자료 조각 축소 → (2순위) 축어록은 원문 자르기 대신 기존 map-reduce로 요약 압축 → (3순위) 대화 히스토리는 최근 K턴만 원문 유지 + 이전 턴은 rolling summary로 압축, 순서로 처리. 그래도 초과 시 "일부만 반영했다" 안내 문구로 사용자에게 알림(침묵 처리 금지). ②·④ 완료 조건에 강제 재현 테스트 추가 |
| SSE 스트리밍 계약(`type: progress\|chunk\|done\|cancelled\|error`)을 신규 `/api/chat/send`가 다른 이벤트 스키마로 만들면 프론트 공통 파서 재사용 불가 | 티켓②에서 기존 이벤트 타입 네이밍 규칙을 그대로 계승(구조 설계에도 명시됨) — 완전히 새 스키마 설계 금지 |
| `analyze_stop`/`_stop_llama_server`가 상주 서버를 강제 종료하는 방식 — 채팅 스트리밍 중 다른 사용자 액션(예: 새 대화 시작)이 실수로 `stop`을 트리거하면 진행 중 스트림이 전부 끊김 | 티켓②에서 "새 대화 시작"과 "중지"를 별개 액션으로 명확히 분리(새 대화는 서버 프로세스에 영향 주지 않고 프론트 상태만 전환) — 완료 조건에 검증 항목 추가 |
| `SessionRecord` 타입에 필드 추가(`chatConversationIds?` 등) 시 기존 저장된 `_사례정보.json` 파일(구버전 데이터, 이 필드 없음)을 읽을 때 타입 에러 없이 하위호환 | 옵셔널 필드로만 추가(구조 설계에도 `?` 표기 이미 반영) — 티켓④ 완료 조건에 "신규 필드 없는 구버전 사례 폴더 로드 시 에러 없음" 확인 항목 추가 |
| 대화 영속 저장 파일이 앱 비정상 종료 시 유실(요구사항 §8 테스트 필수 대상에 이미 명시) | 티켓②에서 저장 시점을 "매 메시지 완료 시 즉시 append"로 설계(전체 히스토리 매번 덮어쓰기가 아니라) — 완료 조건에 강제 종료 시뮬레이션 테스트 추가 |

## 5. 아키텍처 문서 갱신 계획

- ② 완료 후: `CLAUDE.md` "백엔드 API" 표에 `/api/chat/*` 행 추가
- ③ 완료 후: 같은 표에 `/api/reference/*`·`/api/embed/*` 행 추가, "파일 구조" 섹션에 참고자료 창고 경로 추가
- ④ 완료 후: 별도 갱신 없음(신규 엔드포인트 없음)
