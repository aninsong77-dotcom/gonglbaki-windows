## 0. 문서 성격

이 문서는 2026-07-19~07-20 두 세션에 걸쳐 확정된 사항을 하나의 로드맵 기획으로 정리한 것이다.

1. 07-19 세션: 분석 페이지를 채팅 UI로 재설계하기로 결정, 요약+대화 엔진을 Qwen3-4B로 통일 결정, 4단계 순차 로드맵(①Qwen 통합 → ②대화형 UI → ③참고자료 RAG → ④사례서랍 연동) 합의, Qwen3-4B 프리뷰 테스트로 속도·만족도 확인.
2. 07-20 세션(본 문서): ③RAG 단계의 임베딩 방식·벡터 저장소·파일 형식, ②UI 단계의 범위, 작업명을 사용자가 최종 확정. **재검토·조정 의견 없이 그대로 진행 승인됨.**

4단계를 각각 **독립적으로 완료·검증 가능한 이슈 티켓**으로 분리한다. 다중 레이어(FE+BE+데이터모델) 변경이므로 본 기획 완료 후 impl-planner의 코드베이스 전수조사 기반 작업계획서로 이어진다.

## 1. 목적

- 곤글박이 분석 페이지(`src/pages/Index.tsx`의 "분석" 패널)를 **클로드 대화창과 같은 채팅 UI**로 재설계한다.

## 3. 전체 아키텍처 판단

**Python Flask 백엔드(`server/app.py`)에서 AI 관련 처리를 전담한다.** 근거:

- 기존 요약 파이프라인·`llama-server` 상주 프로세스 관리가 이미 이 계층에 있음 — 대화·RAG도 같은 계층에서 확장하는 것이 레이어 책임 분리와 일관됨.
- hwpx 파싱(③단계 참고자료 처리)은 이미 Python(`~/.claude/skills/hwpx/scripts/hwpx2md.py`)으로 존재 — 이식 재사용.
- Electron 메인 프로세스(`electron-main.cjs`)/`preload.cjs`는 지금까지 창 제어·서버 spawn·파일 선택 다이얼로그 IPC(`caseDrawerAPI`)만 담당해 왔다 — AI 로직·RAG 검색은 계속 Flask REST/SSE(`http://127.0.0.1:5577/api/...`)로, 참고자료 파일 선택만 기존 IPC 패턴(`case-select-file`류) 재사용.
- 프론트(`src/pages/Index.tsx` 분석 패널)는 화면·상태 관리만 담당, AI 판단·검색 로직은 전부 백엔드.

상세 API·컴포넌트 구조는 `structure.md`에 정리.

## 4. 티켓 분리

### 티켓 ①: Qwen3-4B 엔진 통합 (요약 엔진 교체)

**목표**: 기존 Kanana 기반 회기 요약 파이프라인의 모델을 Qwen3-4B로 교체하고, 이후 티켓(②③④)이 공용으로 쓸 대화 엔드포인트의 기반을 마련한다.

**요구사항**:
- `server/app.py`의 `LLM_MODEL_FILE`/`LLM_MODEL_URL`을 Qwen3-4B-Q4_K_M gguf로 교체(모델 배포처는 기존 GitHub Release 자산 패턴 유지 — 신규 자산 업로드 필요).
- 채팅 템플릿을 Kanana(Llama3 계열)에서 **Qwen3 ChatML + `/no_think`**로 전환. `_analyze_ask_llm`/`_reduce_partials`가 구성하는 프롬프트 포맷을 Qwen 형식으로 재작성.
- 기존 map-reduce 요약 결과 품질이 Kanana 대비 퇴행하지 않는지 확인(같은 검증 방식 — 더미 대본 A/B 비교, `요약단어_테스트/` 관례 재사용).
- 모델 다운로드 UI(`analyze_model_download` SSE, `src/pages/Index.tsx` 281행대 관리 패널)의 용량 표시(`model_size_mb=1452`)를 Qwen3-4B 실제 용량으로 갱신.
- 기존 "빈출 단어"(Kiwi) 기능은 영향 없음 — 그대로 유지.

**완료 조건**:
```
[ ] server/app.py 모델 교체 + 프롬프트 포맷 Qwen ChatML로 전환

[ ] 모델 다운로드/삭제 UI 용량 표시 갱신

```

### 티켓 ②: 대화형 채팅 UI

**목표**: 분석 패널을 클로드 대화창 형태의 채팅 UI로 재설계. 요약 결과 표시와 자유 대화를 한 화면에서 처리.

**요구사항** (전부 이번 범위, 후순위 없음):
- 채팅 형태 UI: 메시지 말풍선(사용자/AI 구분), 입력창 + 전송 버튼, 스크롤 영역.
- **스트리밍 응답 표시** — 기존 SSE 패턴(`analyze_summarize`와 동일한 `text/event-stream`) 재사용, 토큰이 오는 대로 화면에 이어붙임.
- **세션 내 히스토리** — 채팅 창을 여는 동안 이전 주고받은 메시지가 위로 쌓여 유지됨(멀티턴 대화 컨텍스트를 백엔드에 함께 전달).
- **대화 영속 저장** — 앱을 껐다 켜도 이전 대화가 남음. 저장 위치·단위는 §6 데이터 흐름 참조(사례별 폴더 안에 저장, `structure.md`에서 파일 스키마 확정).
- **마크다운 렌더링** — AI 응답의 목록·강조·코드블록 등을 서식 있는 형태로 표시(기존 `HwpxBlock` 미리보기와는 별개의 렌더러 필요).
- **새 대화 버튼** — 현재 히스토리를 접고 새 대화를 시작(기존 저장된 대화는 보존, 목록에서 다시 불러올 수 있어야 함 — 대화 여러 개가 누적되는 구조).
- 기존 "회기 요약" 동작(전체/내담자만/상담자만)은 채팅 UI 안에서 "요약해줘" 류의 액션 버튼 또는 첫 메시지로 자연스럽게 통합 — 완전 자유 대화와 회기요약 기능이 하나의 채팅 흐름 안에 공존.

**완료 조건**:
```
[ ] 채팅 UI 컴포넌트 구현(말풍선·입력창·스크롤) — 화면 상태(로딩/스트리밍중/에러/빈 대화) 전부 정의
[ ] SSE 스트리밍 대화 왕복 정상 동작
[ ] 세션 내 멀티턴 컨텍스트 유지 확인(이전 대화 참조한 질문에 정상 응답)
[ ] 대화 영속 저장·재로드 확인(앱 재시작 후 이전 대화 목록에서 열림)
[ ] 마크다운 렌더링 확인(목록/강조/코드블록)
[ ] 새 대화 시작 → 기존 대화 보존 + 목록에서 전환 확인
[ ] 기존 회기 요약 기능이 채팅 흐름 안에서 회귀 없이 동작
```

### 티켓 ③: 참고자료 RAG

**목표**: 상담 이론·강의자료 등 참고자료를 등록하면, 채팅에서 그 내용을 근거로 답하는 기능.

**요구사항**:
- 참고자료 등록 UI: 전체 공통 자료 창고(사례 무관, 앱 전역) — 파일 추가/목록/삭제(삭제는 기존 파일시스템 삭제 방식, 자동 만료 없음).
- 지원 형식: **PDF, hwpx, txt, md**.
  - PDF: 텍스트 추출(파싱 라이브러리는 impl-planner 단계에서 기존 의존성과 충돌 없는 것으로 선정 — 표/레이아웃 보존이 필수는 아님, 강의자료 텍스트 검색용).
  - hwpx: `~/.claude/skills/hwpx/scripts/hwpx2md.py` 이식/재사용.
  - txt/md: 그대로 사용.
- 텍스트 조각화(chunking) → 각 조각을 `llama-server` 임베딩 엔드포인트(gguf 임베딩 모델, bge-m3 계열)로 벡터화.
- 벡터 저장: numpy 배열 + JSON(조각 원문 + 메타데이터 매핑) — 참고자료 창고 전용 로컬 파일로 저장(경로는 `structure.md`에서 확정).
- 검색: 사용자 질문을 같은 임베딩 모델로 벡터화 → 코사인 유사도로 저장된 조각 중 상위 N개 선택 → 대화 프롬프트에 컨텍스트로 주입(RAG).
- 임베딩 모델 다운로드는 기존 요약 모델 다운로드 UI(SSE 진행률 표시)와 동일한 패턴으로 별도 선택 설치.
- 참고자료를 참조해 답했을 때, 어떤 자료의 어느 부분을 근거로 했는지 **출처 표시**(최소한 파일명 단위) — 상담 관련 조언의 신뢰성 확보를 위해 필요.

**완료 조건**:
```
[ ] 참고자료 등록/목록/삭제 UI(전역 자료 창고)
[ ] PDF/hwpx/txt/md 4종 파싱 → 텍스트 조각화 확인
[ ] 임베딩 모델 다운로드 UI(기존 패턴 재사용) + 벡터화 파이프라인 동작
[ ] numpy+JSON 벡터 저장/로드 확인
[ ] 질의 → 유사 조각 검색 → 프롬프트 주입 → 응답에 참고자료 반영 확인
[ ] 응답에 출처(파일명) 표시
[ ] 참고자료가 하나도 없을 때 RAG 없이 일반 대화로 정상 폴백
```

### 티켓 ④: 사례서랍(CaseDrawer) 연동

**목표**: 채팅 UI에서의 대화·요약이 사례서랍의 축어록 데이터와 연결되어, 특정 내담자·회기를 대상으로 한 대화가 가능해지고, 필요 시 결과가 사례 폴더에 남는다.

**요구사항**:
- `CaseDrawer.tsx`의 `SessionRecord`(§관련 파일 조사)에서 회기를 선택하면, 그 회기의 축어록을 컨텍스트로 채팅을 시작할 수 있음(기존 "분석" 패널이 특정 축어록 텍스트를 대상으로 동작했던 방식 계승).
- 채팅 결과(요약본)를 기존 `SessionRecord.analysis`(FileRef) 슬롯에 저장하는 흐름 — 기존에는 "결과 저장" 버튼을 눌러야 파일로 남는 구조였음(자동 연동 안 됨, §requirements 배경 기록). 이번 티켓에서 그 결과 저장 흐름을 채팅 UI 안에 자연스럽게 포함할지, 기존처럼 명시적 저장 버튼으로 유지할지는 **impl-planner 단계에서 UI 세부 설계로 확정**(본 requirements에서는 "명시적 사용자 액션으로 저장, 자동 덮어쓰기 없음" 원칙만 고정).
- 사례별 축어록을 대상으로 한 대화와, 참고자료(③)를 근거로 한 대화가 **같은 채팅 창 안에서 함께 참조** 가능해야 함(예: "이 회기 내용을 이론 A 관점에서 봐줘" 같은 질문에 축어록 컨텍스트 + RAG 컨텍스트를 동시에 활용).
- 온디바이스 원칙 재확인: 사례 데이터는 여전히 사용자 PC 파일로만 존재, 이번 연동으로 외부 전송 경로가 생기지 않음.

**완료 조건**:
```
[ ] CaseDrawer에서 특정 회기 선택 → 채팅 컨텍스트로 축어록 연결 확인
[ ] 채팅에서 만든 요약을 SessionRecord.analysis에 저장(명시적 사용자 액션)
[ ] 축어록 컨텍스트 + 참고자료(RAG) 컨텍스트 동시 활용 질의 정상 동작
[ ] 사례 데이터 외부 전송 없음(로컬 전용) 재확인
```

## 5. 화면 상태 (②UI 필수 정의)

`src/pages/Index.tsx` 분석 패널을 대체하는 채팅 UI가 반드시 정의해야 하는 상태:

| 상태 | 설명 |
|---|---|
| 빈 대화(초기) | 대화 없음 — 안내 문구 + "요약 시작"/"질문하기" 등 시작 액션 |
| 메시지 전송 중 | 사용자 메시지 표시 직후, AI 응답 대기(스트리밍 시작 전) |
| 스트리밍 중 | AI 응답이 토큰 단위로 이어지는 상태 — 중지 버튼 노출(기존 `analyze_stop` 패턴) |
| 정상 완료 | 응답 완료, 다음 입력 가능 |
| 에러 | 모델 미다운로드/서버 연결 실패/컨텍스트 초과 등 — 원인별 안내 문구 |
| 모델 미준비 | 요약 모델 없음(기존 `analyzeModelReady` 패턴 계승) — 대화 시작 전 다운로드 유도 |
| 참고자료 검색 중(③ 이후) | RAG 검색 단계가 별도로 눈에 보일지, 스트리밍 중 상태에 흡수할지는 impl-planner 단계에서 확정 |

## 7. 제외 범위 (이번 로드맵에 포함하지 않는 것)

- 참고자료의 **사례별 분리**(공통 창고 하나로 확정 — 사례마다 다른 자료 세트를 두는 기능 없음).
- 참고자료 **자동 삭제·만료 알림**(기존 수동 삭제로 충분, 신규 개발 없음).
- 외부 클라우드 임베딩/LLM API 연동(완전 온디바이스 유지, `llama-server` 로컬 구동만).
- FAISS/Chroma 등 외부 벡터DB 라이브러리 도입(초경량 자체 구현으로 확정).
- PDF의 표/레이아웃 정밀 보존 파싱(참고자료는 텍스트 검색용 — `parse_pdf`(MCP) 수준의 정밀 파싱은 이번 범위 아님. 필요성이 드러나면 별도 트랙에서 검토).
- 여러 사용자 간 대화·참고자료 공유(로컬 단일 사용자 전제 유지).
- 대화 내용의 검색·필터(과거 대화 중 특정 키워드 검색) — 목록에서 열람만, 전문 검색 기능은 이번 범위 아님.
- 참고자료 자동 업데이트(원본 파일이 바뀌면 자동 재임베딩) — 재등록은 사용자가 수동으로 다시 추가.

## 8. 테스트 필수 대상

```
[테스트 필수 대상]
- 엔진 교체(①): 프롬프트 포맷 전환 후 요약 품질 회귀 없음(정성 비교, 기존 A/B 검증 관례)
- 스트리밍 안정성(②): 긴 응답 도중 연결 끊김/중지 버튼 처리(기존 ConnectionAbortedError/BrokenPipeError 처리 패턴 계승)
- 대화 영속 저장(②): 앱 비정상 종료 시 마지막까지의 대화가 유실되지 않는지(저장 시점 설계 확정 필요)
- RAG 근거 정확성(③): 참고자료에 없는 내용을 있는 것처럼 답하지 않는지(환각 방지) — 근거 없으면 "참고자료에서 찾지 못했다"고 답하는 폴백 확인
- 파일 파싱 견고성(③): PDF/hwpx 파싱 실패 시(암호화·손상 파일 등) 전체 등록 흐름이 죽지 않고 개별 파일만 에러 처리
- 프라이버시(전체): 축어록·참고자료 내용이 터미널/로그에 남지 않음(기존 원칙 계승, `feedback_privacy_transcript` 메모리 참조)
```
